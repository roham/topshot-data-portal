## Defects Found

### D1 — Index math: value 5149.06 instead of ~100 (CRITICAL — fixed)

**Surface:** `/`, `/indices/grail`, `/indices/rookies` — ALL active chart pages.

**Evidence:** Homepage KPI text `tracking-tight">5149.06` for GRAIL and `tracking-tight">219.46` for ROOKIES at default 30D lookback. A 51x basket move in 30 days is not market-realistic.

**Root cause:** Per-edition baseline normalization. Formula was:
```
I(d) = 100 × Σ_i w_i × (mcap_i(d) / mcap_i(d_0))
```
Single edition with anomalous baseline (e.g., `lowest_ask_price = $0.01` outlier on one day → `market_cap = circulation × 0.01 ≈ tiny`) produces a per-edition ratio in the millions. Multiplied by even a small weight `w_i` and summed, drags the basket index into the thousands.

**Fix:** Basket-level normalization (S&P/CL50/Russell standard):
```
I(d) = 100 × (Σ_i w_i × mcap_i(d)) / (Σ_i w_i × mcap_i(d_0))
```
Outliers wash out at the basket level. Denominator only goes to zero if the entire basket has zero recorded mcap on `d_0`.

**Applied to:** `lib/indices/grail-synthesizer.ts`, `rookies-synthesizer.ts`, `ts50-synthesizer.ts`.

**Commit:** `6cd9c6b` — `[qa-fix] critical: index math`.

**Status:** ✅ FIXED. Re-verify after Vercel deploy.

### D2 — `/market-cap` takes 91 seconds (HIGH — deferred)

**Root cause (suspected):** Default Vercel function timeout (10s on hobby, 60s on pro) — the page fans out many heavy supabase reads in parallel; one or more is timing out. No `maxDuration` exported on the page.

**Fix path:**

### D3 — Chart SVG not server-rendered (LOW — expected)

**Evidence:** `recharts-responsive-container` present but no `recharts-area`/`recharts-line` paths in served HTML.

**Root cause:** `TS50IndexChart` is `"use client"`. Recharts renders client-side after hydration. The empty container is what server-renders.

**Status:** NOT A DEFECT — expected behavior. Mentioned only because it made HTML-grep verification incomplete; real visual QA requires Chrome MCP or Playwright headless.
